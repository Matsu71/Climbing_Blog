# 日本クライミングジム・データベース構想

## 目的

日本国内のクライミングジムを可能な限り網羅し、単なる店舗一覧ではなく、地図・時系列・施設スペック・評価を統合したデータベースを構築する。

主な問い：
- 現在、日本にはクライミングジムが何施設あるのか
- どの地域に集中しているのか
- 年ごとに何施設が開店し、何施設が閉店したのか
- 日本のクライミングジム数はどのように増減してきたのか
- 各ジムはボルダー、リード、トップロープ等のどの設備を持つのか
- 各ジムの規模・特徴・料金・設備はどう違うのか
- 利用者から評価されているジムはどこか

## 1. 地図サービス

日本地図上に全ジムを表示する。

### 基本表示
- 営業中
- 閉店
- 休業中 / 状態確認中
- ボルダリング中心
- リード設備あり
- トップロープ設備あり
- その他特殊設備あり

初期表示では営業中の施設を中心にし、閉店施設は時系列表示や履歴表示で確認できるようにする。

### 地図フィルター候補
- 都道府県
- 市区町村
- 営業状態
- Boulder / Lead / Top Rope
- ジム規模
- 評価
- 営業開始年
- チェーン / 独立系
- トレーニング設備
- 初心者向け設備
- キッズ対応

## 2. 年別の開店・閉店データ

各施設について可能な範囲で開店日・閉店日を保存する。

日付精度も保存する。
- exact: YYYY-MM-DDまで確認
- month: YYYY-MMまで確認
- year: 年だけ確認
- estimated: 推定
- unknown: 不明

### 年次分析
各年について以下を算出する。
- 新規開店数
- 閉店数
- 純増減 = 開店数 - 閉店数
- 年末時点営業施設数
- 都道府県別営業施設数
- 市区町村別営業施設数

これにより「日本のクライミングジム数の推移」を時系列グラフとして表示する。

## 3. ジム基本データ

推奨フィールド：

```text

closed_date_precision
```

`gym_id` は名称変更や移転が起きても追跡できる内部IDとする。

## 4. クライミング設備

```text
has_bouldering
has_lead
has_top_rope
has_speed
bouldering_only
wall_height_m
max_wall_height_m
wall_area_m2
facility_floor_area_m2
max_overhang_deg
```

面積については「施設全体面積」「クライミングエリア」「壁面積」を混同しない。公式サイトが単に「○○m²」と記載している場合は、その値が何を意味するかも保存する。

### トレーニング設備候補
- Hangboard
- Campus Board
- MoonBoard
- Kilter Board
- Tension Board
- Spray Wall
- System Board
- Weight Training

## 5. 利用情報

変更頻度が高いため、値と更新日をセットで扱う。

候補：
- 1日利用料金
- 初回登録料
- 月会費
- レンタルシューズ
- レンタルチョーク
- 営業時間
- 定休日
- 駐車場
- 更衣室
- シャワー
- ロッカー
- キッズ利用条件
- 初心者講習

## 6. ジム規模

単一の「広さランキング」では誤解が出るため、可能なら以下を別々に保存する。

1. 施設床面積
2. クライミングエリア面積
3. 壁面積
4. 最大壁高
5. Boulder / Leadそれぞれのエリア規模

公式数値が存在しない施設では、推測値を事実として保存しない。

## 7. ブログ独自のユーザー評価

Google評価とは独立した評価システムを持つ。

初期版は以下で十分。
- 総合評価 1〜5
- コメント
- 訪問時期
- 主に利用したカテゴリー（Boulder / Lead等）

将来的な詳細評価候補：
- 課題・ルートの質
- 課題の多様性
- 初心者の利用しやすさ
- 上級者向け充実度
- トレーニング設備
- 混雑
- 清潔さ
- アクセス
- コストパフォーマンス

評価数が少ない施設を単純平均だけでランキング上位にしないよう、評価件数も明示する。ランキング導入時はベイズ平均等も検討する。

### UGC運用
- 同一利用者による大量投稿を抑制
- スパム対策
- 誹謗中傷・個人情報の投稿禁止
- 店舗への事実断定を伴う重大な投稿はモデレーション対象
- 利用規約と投稿ガイドラインを用意

## 8. Google Maps評価の扱い

Google Mapsの評価を表示する場合、画面からスクレイピングして自前DBへ恒久保存する方式は採用しない。

Google Maps Platform / Places APIを利用し、Googleのポリシーに従って表示する方向を基本とする。

設計上は：
- `google_place_id` は施設IDとの対応用に保存
- rating / user rating count等は原則として必要時に取得・表示
- Google Maps由来コンテンツであることを明確に表示
- 必要なGoogle Maps attributionを付ける
- Googleレビュー本文を扱う場合はレビュアーの帰属表示等、Places APIの要件に従う

ブログ独自評価とGoogle評価は視覚的にもデータ的にも混ぜず、別項目として表示する。

## 9. データソースと検証

候補ソース：
- ジム公式サイト
- ジム公式SNS
- Google Maps / Places API
- クライミング関連団体・施設ディレクトリ
- チェーン公式店舗一覧
- 過去のWebアーカイブ
- 開店・閉店告知
- 信頼できる報道・地域情報

### 情報ごとの根拠を保存

```text
field
value
source_url
source_type
observed_at
confidence
notes
```

重要な履歴データ（開店・閉店等）はできれば複数ソースで確認する。

## 10. 分析記事候補

- 日本にはクライミングジムが何件あるのか
- 日本のクライミングジム数は20年間でどう変化したか
- 1年間に何軒のジムが開店・閉店するのか
- 都道府県別クライミングジム数ランキング
- 人口10万人あたりクライミングジム数ランキング
- 東京・神奈川・大阪等のジム密度比較
- 日本最大級のクライミングジムはどこか
- Lead設備があるジムはどのくらい少ないのか
- ボルダリング専門店と総合クライミングジムの推移
- チェーン系ジムと独立系ジムの分布
- ユーザー評価の高いジム
- 初心者向けジム / 上級者向けジム

## 11. 最終イメージ

ブログ記事と独立データベースを分けず、同じ基礎データから以下を生成できる構成を目指す。

- 全国クライミングジム地図
- ジム詳細ページ
- 条件検索・フィルター
- 年次推移グラフ
- 都道府県・市区町村ランキング
- ジム比較
- ユーザー口コミ
- 分析記事

最初は情報の完全性を優先し、口コミや複雑なランキング機能は基礎データが整ってから追加する。
